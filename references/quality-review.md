# 质量复核与真实素材对照

## 读懂报告

- `invalid_boundary` / `invalid_duration` / `duplicate_uid`：结构错误，修复后才能导出。导出入口会拦截这些错误。
- `overlap`：列出所有启用片段的重叠对（含嵌套区间和不同类型）。重叠可能来自首尾预留，并不证明回合误判。按主场画面确定切点；拼接时避免重复画面。
- `long_segment`：默认大于 30 秒进入复核清单。阈值是排查优先级，不是羽毛球回合长度上限。独立复核命令可用 `--long-seconds` 调整，检测算法不因此变化。
- `peaks_outside_boundary`：编辑切点后，原声学事件可能位于区间外，拍数与字幕应同步检查。
- `zero_short_candidates`：没有检出接发短分，不能据此推断真实录像中没有短分。

报告仅反映当前时间轴，修改后应重新生成。报告不会修改或删除源视频和时间轴，不会自动修剪重叠，不代表人工审片通过。禁用片段不参与导出结构检查。未标记的片段仍需抽查。

## 画面检查

先确认主场范围与固定机位有效时间窗。当前算法使用固定比例区域，并未自动校准球场边界。

对候选查看发球前、第一拍、最后一拍和结束后画面，必要时播放完整候选。长片段增加中段检查，区分连续对拉与邻场声音连接起来的多段比赛。静态截图只能辅助定位，不能独立证明回合连续、球已落地或每个音峰都是一次击球。

如果抽查出现相同类型的系统性错误，扩大同类抽查并记录证据；可人工修正时间轴后导出。不要为了追求数量或“零误差”盲目删片。未完成逐段复核时，以候选结果交付并说明已查范围。

## 接发短分诊断

`analysis_diagnostics.serve_kill` 中的数量是声学事件筛选统计，不是独立真实得分数：

1. `input_events`：稳定机位窗口内声学事件。
2. `energy_pass`：通过能量门槛。
3. `serve_interval_pass`：找到符合时间间隔的发球事件。
4. `post_silence_pass`：通过接发后静音条件。
5. `pre_silence_pass`：通过发球前静音条件，即送入视觉核验的候选数。
6. `visual_attempted` / `visual_pass` / `visual_rejected`：视觉筛选统计。
7. `deduplicated` / `selected`：合并相近候选后保留的数量。

`rejected` 保存每个声学阶段的淘汰数；各项之和加 `pre_silence_pass` 应等于 `input_events`。多场地素材在静音阶段大量淘汰时，需要对照真实短分评估漏检。本版本提供诊断，保留原有筛选阈值，未声称改善召回率。旧时间轴诊断缺失不会自动重扫。

## 算法修改的验证方式

从实际素材中选择连续时间窗，人工标注所有主场回合的起止时间，同时包含长回合、快速平抽、网前轻球、短分、捡球和邻场干扰。记录源文件身份和标注理由；不把现有算法输出直接当作真值。

将用于调参的时间窗与留作验收的时间窗分开。比较修改前后：真回合漏检数、无关片段误检数、起止偏差、片段内等待时长。回归测试保护已知行为，真实素材对照检验实际识别能力；两者都不能单独证明普遍准确。

代理视频、顺序解码缓存、可校准场地和连续状态识别属于后续算法工作。试验时必须保持时间映射正确，比较原分析与新分析的边界，计入生成代理的耗时，并始终从原视频导出。
